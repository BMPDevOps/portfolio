Homelab

2019.06 ~ 현재

서버 인프라를 다루는 게 취미입니다. 2019년 6월부터 집에서 서버를 구성하고 운영해 왔습니다. 업무나 프로젝트와 별개로, 직접 환경을 만들고 여러 기술을 붙여보는 공간입니다.

ESXi 서버 2대와 Proxmox VE 서버 1대를 사용하고 있습니다. vSphere에서 vMotion, HA, DRS를 설정했고, 스토리지는 Ceph로 구성했습니다. 네트워크는 10GbE와 2.5GbE를 사용합니다.

그 위에 OKD를 마스터 3노드, 워커 3노드로 구성했습니다. 컨테이너에서 저장 공간을 사용할 수 있도록 Ceph RBD를 StorageClass에 연결했습니다.

배포는 ArgoCD로 관리하고, 이미지와 Helm 차트는 Harbor에 저장합니다. Ansible과 Terraform으로 프로비저닝과 설정 관리를 자동화했으며, Prometheus와 Grafana로 서버와 클러스터 상태를 확인합니다.

컴퓨팅ESXi × 2 / Proxmox VE × 1
영속 스토리지Ceph RBD → OKD StorageClass
배포ArgoCD → OKD (마스터 3 / 워커 3)
관측Prometheus → Grafana

STOOCK에서 만든 친구 서비스

2024.10 ~ 2025.02

STOOCK은 MSA 기반 모의투자 애플리케이션입니다. 저는 OKD 기반 인프라와 배포 자동화를 맡았고, Go(Gin)로 친구 서비스도 만들었습니다.

친구 서비스에는 Neo4j를 사용했습니다. 사용자끼리 어떻게 연결되어 있는지 관계도로 표현하기 좋아서 선택했습니다. 사용자를 노드로 두고 친구 연결을 FRIEND 관계로 저장하니, 사용자 사이의 연결을 그래프 형태로 나타낼 수 있었습니다.

API는 Gin으로 요청을 받고 Controller, Service, Repository를 거쳐 Neo4j에 접근하도록 구성했습니다. 친구 연결을 추가할 때는 두 사용자 노드를 찾은 뒤 MERGE로 관계를 만들었습니다. 친구 목록은 해당 사용자에서 나가는 FRIEND 관계를 따라 조회하도록 구현했습니다.

MATCH (u:User {id: $userID})
MATCH (t:User {id: $targetUserID})
MERGE (u)-[r: FRIEND]->(t)
RETURN r

  • 관계 조회·생성 쿼리

GROUPBEE에서 맡은 인프라와 유저 서비스

2024.06 ~ 2024.09

GROUPBEE는 Kubernetes 기반 그룹웨어 프로젝트입니다. 저는 기술 총괄과 DevOps를 맡으면서 유저 서비스도 개발했습니다.

Naver Cloud의 NKS로 클러스터를 구성하고 Kong API Gateway와 Istio를 연결했습니다. 서비스별로 네임스페이스를 나누고 Helm 차트로 배포 설정을 관리했습니다. Jenkins와 ArgoCD를 연결해 빌드부터 배포까지 자동화했습니다.

사용자 관리에는 FreeIPA를, 세션 관리에는 Redis를 사용했습니다. Employee 서비스에서는 Redis Hash에 저장된 Spring Session 정보를 조회하는 코드를 작성했습니다. 전달받은 키로 principal 관련 값을 읽고, 값이 없으면 null을 반환하도록 구성했습니다.

  • Redis 연결·자료형 설정
  • 세션 Hash 조회 구현

  • Ansible/Terraform을 이용한 Infrastructure as Code 구현 - 인프라 프로비저닝 및 설정 관리 자동화
  • Prometheus + Grafana 모니터링 스택 구축 - 시스템 메트릭 수집 및 대시보드 구성
  • Harbor를 활용한 레지스트리 관리 - 컨테이너 이미지 관리 및 Helm 차트 관리

결과

  • 99.9% 가동 시간 달성 (연간 8시간 이하 다운타임)
  • 자동화를 통한 운영 작업 시간 단축
  • 스토리지 풀 안정적 운영 (데이터 손실 0건)
